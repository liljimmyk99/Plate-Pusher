# AGENTS.md — /web

Read the root `AGENTS.md` first. This file adds rules specific to the React web app. The design canvas linked in root §1 shows every screen below; match it, and where it and this file disagree, this file wins.

## Stack

- React + TypeScript, built with Vite. Tests: Vitest with Testing Library (jsdom).
- **API client:** types generated by `openapi-typescript` into `src/api/schema.gen.ts` (never edit it; `npm run gen:api` after a spec change, `npm run check:api` fails if stale). Calls go through an `openapi-fetch` client in `src/api`, used inside TanStack Query. Failures throw `ApiError` (`status`, `code`, `details`); branch on `code`, never `message`.
- **Server state: TanStack Query**, in memory only, `networkMode: "always"` so offline requests fail visibly.
- **Auth** (same as Penny Pincher): `src/auth` exposes an `AuthService` (`signIn`, `signOut`, `changePassword`, current user and token). Only `src/auth` reads or writes the token, kept in `localStorage` under one key. A `401 unauthenticated` / `session_expired` clears it and shows Sign in; `403 password_change_required` goes to Change password. Never put the password, token or username in a URL or log.
- **Routing:** React Router. Each screen renders a `Page` that sets the tab title and an `h1` that takes focus after navigation.
- **UI: shadcn/ui**, `new-york` style, on Tailwind CSS v4 (`@tailwindcss/vite`), components in `src/components/ui/`, owned by us.
  - Add components with `npx shadcn@latest add <name>`. Never edit a primitive for a one-off look; wrap it outside `ui/` or add a `cva` variant. Edits inside `ui/` are only for app-wide rules, each with a comment.
  - Radix imports only inside `src/components/ui/` (ESLint enforces it).
  - Icons: `lucide-react`, named imports only. Toasts: Sonner, through one `toast` helper.
- **Charts:** no charting library. Hand-built SVG components on the design tokens, one per chart type (e.g. `LineChart` for progression, `WeeklyBars`, `MuscleGroupBars`), shared by every screen. Every chart has a text alternative (a nearby data table or per-point labels).
- Do not add a major dependency without noting it in the root file.

## Theme: Forge

The app is dark only. Tokens live in `src/index.css` as shadcn CSS variables; components use the variables, never raw hex.

```css
:root {
  --radius: 0.625rem;
  --background: #0A0C10;   --foreground: #ECEEF2;
  --card: #11141A;         --card-foreground: #ECEEF2;
  --popover: #171B23;      --popover-foreground: #ECEEF2;
  --primary: #FF7A1A;      --primary-foreground: #1A0B00;   /* accent: actions */
  --secondary: #2563EB;    --secondary-foreground: #FFFFFF; /* info actions */
  --muted: #171B23;        --muted-foreground: #949CAE;
  --accent: #1C212B;       --accent-foreground: #ECEEF2;
  --destructive: #F2555A;
  --border: #242A36;       --input: #2E3543;   --ring: #60A5FA;
  --chart-1: #FF7A1A;  /* working weight */
  --chart-2: #60A5FA;  /* target, e1RM, reps */
  --chart-3: #FDBA74;  --chart-4: #1D4ED8;  --chart-5: #94A3B8;
  --sidebar: #0D1015;  --sidebar-primary: #FF7A1A;  --sidebar-accent: #171B23;  --sidebar-border: #1C212B;
  --font-sans: Inter, system-ui, sans-serif;
  --font-heading: "Space Grotesk", sans-serif;
  --font-mono: "JetBrains Mono", monospace;
}
```

- **Roles:** the primary (accent) colour means *act* (main buttons, Done, progress, streaks, PR badges); blue means *information* (targets, the target prompt, chart lines, links, focus). Drop sets use soft orange (`--chart-3`) badges, supersets blue badges, planned or empty states dashed borders.
- **Fonts** are self-hosted (CSP: no new font origin). Numbers use `font-variant-numeric: tabular-nums`.
- **Dark only.** There is no light theme and no theme setting; don't add `.light` tokens or a `prefers-color-scheme` switch.
- **Accent colour** (Settings): Orange (default), Blue `#3B82F6`, Green `#22C55E`, Red `#EF4444`, or a custom 6-digit hex. Stored in `localStorage`. Applying it sets `--primary`, `--chart-1` and `--primary-foreground`, picking black or white by WCAG contrast. A custom colour under 3:1 against the background is lightened for text and chart use. With Red, destructive actions switch to an outlined style; with Blue, the info colour switches to teal, so roles stay distinct. Set the variables from script on `document.documentElement` (no inline `<style>`; CSP).

## Rules

- **Weights** arrive as integer hundredths of a pound. Format and parse them in one utility (`src/lib/weight.ts`): `13500` ↔ `"135"`, `250` ↔ `"2.5"`, bodyweight `0` ↔ `"BW"`, `2500` ↔ `"BW + 25"`, assisted `500` ↔ `"Assist 5"` and `0` ↔ `"Unassisted"` (the formatter takes the exercise's load type). On assisted exercises the weight stepper's − means *less assistance*, and charts say "lower is better". Never do arithmetic on floats or formatted strings.
- **Durations** are integer seconds, shown as `45s` or `1:30`.
- **Dates** are `YYYY-MM-DD` from `src/lib/dates.ts`. A new workout's date is the device's **local** date; never derive it from `toISOString()`.
- **Shorthand** is parsed by the API (`sets:expand`), not in the browser, so there is one parser.
- **Online-only in v1:** no workout data in localStorage or IndexedDB. A set that fails to save stays visible with an error and a Retry button. **UI preferences** may be stored locally, under one `prefs` key: accent colour, weight step, keep-screen-awake, sidebar state, last-opened chart.
- Keep server state in TanStack Query, not copied into component state.
- **Content-Security-Policy** (set by the host reverse proxy; its site block lives in `/deploy`): no inline scripts or `<style>` elements, no `eval`. Loading from a new origin means updating the policy in the same change.
- **Responsive grids:** card and stat grids use auto-fit columns (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4` or `repeat(auto-fit, minmax(200px, 1fr))`), never a fixed column count that squeezes text at phone width. Chip rows that can overflow scroll sideways.
- **Labels with names in them** are built as one string (e.g. `Create a ${group} Routine`), never adjacent text nodes in a flex container, which drops the spaces.

## Layout and navigation

- **Desktop-first** shell: a sidebar with **Today, Routines, Exercises, History, Analytics, Import**, and at the bottom a **profile button** (avatar with initials, display name, role, chevron). It opens a menu above it with the name and @username, **Settings**, **Admin** (admins only) and **Sign out**. On the Settings page the profile button shows as active. The sidebar becomes a sheet below 768px.
- **The workout screen is phone-first** and full-screen on phones (no sidebar).

## Screens

- **Sign in / Change password:** same as Penny Pincher.
- **Choose your split (first sign-in only):** shown before anything else while `onboarded` is false. Five cards (Body-part, Push / Pull / Legs, Upper / Lower, Full body, Custom), each listing the routine groups it creates, then the weekly goal (a stepper, default 3). "Skip" is Custom with the default goal. One screen, no wizard.
- **Today (landing):** the workout in progress (Resume, with progress and the next entry), this week (goal progress such as "2 of 3", a Monday–Sunday strip of days trained, weekly streak, volume and reps), Start from a routine (the user's order, one marked **Suggested**), **Start Empty Workout**, and the last workout (with a PR badge when it set one). On a phone, Resume is the largest element.
- **Workout (logging, phone-first):**
  - One entry at a time, with the full list one swipe or tap away. Each entry shows the target (`3 × 10 @ 135`), the variation when it isn't the only one (e.g. "Incline bench"), the last time's numbers, and the exercise's how-to notes as a collapsible line.
  - Each set row is prefilled from the target; **Done** logs it as shown in one tap. Weight and reps are steppers with numeric inputs (`inputmode="decimal"` / `"numeric"`); the weight stepper moves by the weight step from Settings.
  - A shorthand field adds sets at once: `3x10 @135`, or a drop set as `10@135 > 8@115 > 6@95`, `10 @135>115>95` (same reps) or `@135 10>8>6` (same weight). Steps may go up as well as down.
  - A **drop-set entry** shows its target as steps (`10 @ 135 → 8 @ 115 → 6 @ 95`); each set row is prefilled with those segments, each with its own weight and reps, and **Done** logs the whole drop.
  - **Add drop** on any set adds a segment below it, for an unplanned drop.
  - Supersets show one round at a time, members stacked (A, B, …), then the next round, with a round progress bar. A drop-set member shows its steps inside the round, the same as a drop-set entry.
  - Entry menu: Skip, Swap exercise, Add note. Workout menu: Add exercise or superset, Reorder, Discard.
  - After an entry is finished and it differs from the target: an inline prompt with **Update** and **Keep**. Straight: "Update target to 140?" / "Keep 135". Drop: shows the old and new steps side by side. Never a blocking dialog mid-set.
  - **Finish** shows the summary: totals, new PRs, unanswered target prompts.
  - Keep the screen awake with the Wake Lock API while a workout is open, unless turned off in Settings (ignore it where unsupported).
  - States per set row: pending (steppers + Done), done (orange tint, check, tap to undo), failed save (red tint, message, **Retry**).
- **Routines:**
  - **List:** routines **by group** (group heading with its count and "+ Add"), then **No group**; routines in the user's order within each (drag, or Move up/down), each row showing name, item count, last done, and **Created … · Modified …**. An empty group shows a dashed "Create a <Group> Routine" button. Groups can be added, renamed, reordered and deleted (their routines move to No group). Selecting a routine on desktop shows its items in a side panel with Edit, Start workout and Duplicate; on a phone each row opens the editor.
  - **New routine:** opened from a group's "+ Add" (group prefilled, name suggested such as "Legs C"), from the main "+" (no group chosen), or as a copy of an existing routine. Has Name and Group fields. Shows the empty state "No exercises yet" with **+ Add exercise** and **+ Add superset**, plus "Copy from…". **Save** is disabled until there is a name and at least one item.
  - **Editor:** name, then items as exercise or superset cards. Each card shows its variation and variant (`Incline bench · 3 × 10 @ 20`) and edits its target load, with a note naming the other routines that share it ("Also in Arms B"). Changing the scheme picks another variant: a **Straight / Drop set** toggle (`Segmented`) plus sets and reps fields; the card offers the variation's existing variants first, and a new scheme asks for its target load. A drop variant's steps are edited as a list (reps and weight, add and remove steps), with quick fills for "same reps, less weight" and "same weight, fewer reps"; there is no direction rule to flag. A superset card lists its members, each with its own variation and variant.
  - **Add exercise (variation picker):** search, muscle-group filter chips (scrolling row), then the exercise list. Choosing an exercise opens one shared `VariationPicker` component (used on desktop and phone): **1 · Which variation?** (the exercise's variations as chips, plus **Other…**, which names a new one), then **2 · Sets & reps for <variation>** (its existing variants as radio cards with the routines using them, plus **New scheme** with the Straight / Drop toggle and fields). The button names the choice ("Add Incline bench · 4 × 8"). "Can't find it? + New exercise" opens New exercise.
  - **Add superset:** reuse an existing superset in one tap, or build one: optional name, members A, B, … (any exercise, including the same one twice with different variations), each with the variation picker's choices, reorder, **+ Add member** (at least two), **Add superset to routine**.
  - **New exercise:** name, muscle groups as multi-select chips with one **primary** (marked ★, chosen in a "Primary" select; a hint says only the primary counts for volume and streaks), tracking (Weight × reps / Duration), **Load** (Weighted / Bodyweight / Assisted, with a one-line hint for each: "the weight you lift", "weight added to you", "assistance — less is better"), How-to notes, and the first scheme for this routine. "Create & add to routine" does both.
- **Exercises:** library grouped by primary muscle group, with search, a muscle-group filter (matches secondary groups too) and an archived filter. Each row shows how many variations and variants the exercise has and when it was last done.
- **Exercise page** (root §6, use case 16), from one `exercises/{id}/page` call:
  - **How to do it:** the how-to notes as a list, with Edit notes. "Shown under the exercise name while you log it."
  - **Overview:** best estimated 1RM over time across all variants, weekly reps and volume for this exercise, PRs, last done. Stat cards use auto-fit columns.
  - **Variants**, in two groups: **Isolated**, subdivided by **variation** (each with its name, variant count and Rename, its variant cards, and an **Add variant** tile), with **+ Add grouping** below; and **In supersets** (titled with the other members, e.g. "with Tricep Pushdown"). Each variant is a card: scheme and target load (`4 × 10 @ 115`), style badge, routines that use it, last done, best, and a sparkline of its working weight. Planned variants with no history say so. Archived variants and variations sit behind a filter.
  - **Variant detail** (a section that expands on desktop, a separate view on phone): progression chart of working weight per workout (each step's weight as its own line for a drop variant, duration for timed ones) with the target load as a step line and estimated 1RM where it applies; its history with every set; edit the target load; archive.
  - On desktop, two or more variants can be compared on one chart (e.g. 3 × 14 against 4 × 10, or Standing against Incline).
- **History:** workouts grouped by week (Mon–Sun), each week heading with its goal progress ("2 of 3", "3 of 3 ✓"), filters for date range and routine (including "Empty workouts"), paged with "Load older workouts". Desktop: selecting a workout shows its detail beside the list. Phone: a list whose rows open the detail. Detail: date, time and duration, totals (volume, reps, sets, new PRs), every entry with its planned target and each logged set (drop sets as `12@140 > 10@120 > 8@100`, superset rounds as `A … · B …`, PR sets highlighted, swapped and skipped entries labelled, entry notes), Edit and Delete.
- **Analytics:** tiles (weekly goal streak, this week, volume and reps with change against the 4-week average); workouts per week as bars against a dashed goal line (current week lighter); weekly volume and reps lines; muscle groups this week (volume bars by primary group, plus each group's weekly streak); recent PRs (kind, exercise · variant, value, date); a progression chart with an exercise picker, an Est. 1RM / Working weight toggle and a link to the exercise page.
- **Import:** steps Upload → Review → Import. Accepts `.md` (a Name · Amount · Weight table), `.xlsx` and `.csv`. If the file has no Date column, review asks for the workout's date and optional routine. Review shows each parsed row beside its raw line (e.g. `15x12x12 · 85` → 3 sets: 15, 12, 12 @ 85), the file summary (workouts, sets, similar names, new exercises, problems); **Similar names · same exercise?** (each pair "in file ≈ existing" with **Same exercise** / **Different**, a count still to decide, and the Import button disabled with a note until all are answered); new exercises to create (muscle group, or "Match existing…"); problem rows with the raw row; matched exercises; **Import N workouts**. Below: past imports with **Undo import**, and **Download template** (spreadsheet with Date · Routine · Name · Amount · Weight · Notes).
- **Settings:** sections in this order:
  - Weekly workout goal (stepper).
  - Accent colour (swatches, custom hex field and picker, live preview).
  - Logging (weight step 1 / 2.5 / 5 / 10 lb; keep screen awake switch; "Saved on this device").
  - Muscle groups (rows with exercise count, ↑ ↓, Rename, **Deprecate** / **Restore**; deprecated rows dimmed with a badge; + Add group; delete only for unused groups).
  - Change password (12-character rule shown inline).
  - Signed-in devices (device, signed in, last active, "This device" badge, Sign out per device, **Sign out everywhere else**).
  - Export data (Workout log · CSV with a date range; Full backup · JSON; last export line).
  - Account (name, role, Sign out).
- **Admin panel:** Users (add, reset password) and Status, same as Penny Pincher. Reached from the profile menu.
- **Empty states** for every list, with the one action that fills it.

## Quality

- Keyboard accessible, readable contrast in the dark theme, WCAG A/AA, including every accent colour (check contrast when applying a custom accent).
- **Touch targets:** 44px everywhere; **48px for set controls** on the workout screen (Done, steppers, Add drop).
- Label in name: a control's `aria-label` contains its visible text. Radio-like chip groups use `role="radiogroup"` / `aria-checked`; toggles use `aria-pressed` or `role="switch"`; the profile menu uses `aria-haspopup="menu"` / `aria-expanded`.
- Respect `prefers-reduced-motion`.
- Test: weight formatting and parsing (weighted, BW, BW + added, Assist and Unassisted), the split screen (every option, Skip), the set row's one-tap Done, the weight step setting, planned drop sets (falling, rising and mixed steps, isolated and in supersets), the variation picker (existing variation and scheme, new scheme, Other), picking and creating variants in the routine editor, a superset with the same exercise twice, New routine's disabled Save, the exercise page's grouping by variation and variant detail, unplanned drop segments, superset rounds, the target prompt (Update / Keep, logged weight unchanged), resume after reload, a failed set save with retry, primary muscle group selection, deprecating and restoring a muscle group, accent colour (presets, custom hex validation, contrast-based text colour), import similar-name answers gating Import, and chart text alternatives.
- **PR suite budget:** lint, type check and Vitest together stay under about a minute, so the whole PR check fits in 2 minutes.
- Run `npm run lint && npm run typecheck && npm test` before finishing.
